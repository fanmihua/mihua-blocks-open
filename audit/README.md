# 自动检查

AI 说「对齐了」不算数，跑一遍检查才算数。

```bash
npm run audit:kits                                   # 所有场景、所有组合
npm run audit:kits -- --scene=controls               # 只查控件样张
npm run audit:kits -- --scene=login --variant=centered --spec=mono   # 只查符合条件的组合
npm run audit:kits -- --scene=admin --kits=shadcn,antd               # 只比其中几个组件库
```

`--kits` 用来「先拿两个库探路」：新控件先在源码在自己手里的那个库（shadcn）写一个照规格的参照实现，
再拿 `--kits=shadcn,<新库>` 一对一地对齐；几个库可以同时由不同的人（或 AI 会话）做，最后一起跑完整检查。

需要本机有 Chrome（或者设置 `CHROME_PATH`）。结果写到 `output/audit/report.json`。

## 它怎么工作

1. 打开检查页 `examples/audit.html`：所有登记的组件库（`examples/src/kits.ts`）并排渲染同一个场景、同一个状态，1:1 不缩放。
2. 逐个场景（`examples/src/scenes/`）、逐个组合（规范 × 布局 × 状态……）打开，做这个组合要求的检查。
3. 每项检查在所有组件库里做同样的事，结果逐项对比。数字允许 0.6px 误差（亚像素取整），其余必须完全相同。有一项不一样就失败。

**它不认识任何组件库、任何组件。** 组件库的知识在套件的部件地图（`parts`）里，场景的知识在场景里。接新组件库、加新控件、加新页面，都不用为它们改这里。组件库多了可能暴露量法或环境的问题（第五个库进来时，页面宽过了检查窗口），那时改成对所有组件库成立的通用规则，不开特例。

## 量什么

**按区域量**：场景里标了 `data-region` 的元素各是一个区域，区域里的东西按区域自己的左上角量，区域本身的位置另记。报告直接指到「哪个区域、哪个部件、哪一项」。

| 检查项              | 做什么                                                                                                                                                                             |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 样子 `look`         | 每个区域的位置大小；区域里的文字（位置、字号、字重、颜色）、输入框里的文字和占位符、每个部件的框（位置、大小、底色、边线、圆角、投影、不透明度）、图标（哪一个、位置、大小、颜色） |
| 聚焦 `focus`        | 逐个键盘聚焦，量边线、外圈、轮廓线                                                                                                                                                 |
| 弹层 `popup`        | 真实点击打开，量弹层和每个选项；按 Esc，核对收起。`open: 'hover'` 的（侧栏收起后的子菜单）是鼠标悬停打开、移开收起                                                                 |
| 悬停 `hover`        | 真实鼠标悬停，量底色、文字色、边线、外圈                                                                                                                                           |
| Tab 顺序 `tabOrder` | 从每格开头一直按 Tab，记下依次聚焦到什么（按角色和名字，不按元素）                                                                                                                 |
| 按键 `keys`         | 聚焦以后按键，读场景的状态和焦点                                                                                                                                                   |
| 点击 `click`        | 真实点击，读场景的状态                                                                                                                                                             |

量法的几条规则（对所有组件库一样，不开特例）：

- 边线：真边框，或者 1px 内阴影（Element 这样画边框）；和底色同色的边框算没有；
- 圆角：按看得见的算（超过短边一半的压到一半，百分比换成像素）；
- 投影：只算有偏移或模糊的阴影；只向外扩展的是聚焦外圈，另外量；完全透明的不算；
- 图标：SVG 读 `data-mh-icon`；组件库用 CSS 遮罩画的读遮罩图形里的名字；不是规范图标集的记成 `library`；
- 藏起来的原生 `input`（开关、复选框常这样做）外层看得见，就算在页面上。
- 聚焦、Tab 顺序里的元素按角色和名字记（「menuitem 工作台」），不按标签名：同一个菜单项，有的组件库是 `<li>`、有的是 `<button>`。
- 一个区域里的文字、图标先按内容、再按位置排好再逐项对比：只按位置排，半个像素的高低差就会让顺序翻过来，后面全部错位。
- 同一个颜色的两种写法（过渡中的 `rgba(…, 1)` 和 `rgb(…)`）算一样。
- 把鼠标移开（悬停检查之后、悬停弹层收起时）是两次移动，像真实的鼠标：Radix 的文字提示要等离开以后的下一次移动才关上。
- 边线还按四条边量（`lines`）：表格的行线、表头下面的线只画在下边；四条边一样（普通的框）时按「边线」比。
- 图标：藏起来的（`display: none`）伪元素不算。
- 单选、复选框的 `name` 是这一组的名字，不算它自己的名字。
- **和一个组件库交互时（点击、按键、弹层、聚焦、Tab 顺序），别的格子设成 `inert`**；场景里有对话框这类模态弹层时（场景提供了 `solo`），先复原成「只有这个组件库的弹层开着」，「样子」也一个组件库一个组件库地量。几个模态对话框同时开着时会互相抢焦点（浏览器卡死），Radix 还会把整页设成不能点；真实页面里只有一个。
- 点击可以接着再点几下（`steps`：打开日期面板，再点两天）；按键可以给间隔（`gap`：按人的速度连按两次 Esc）。
- 鼠标操作之前先把目标滚进窗口：组件库一多，页面会比检查窗口宽（双栏登录五格排开要 4000 多 px，后台页面框架五格要 6000 多 px），真实的鼠标点不到窗口外的东西。离窗口左右边缘不到 400px 的滚到窗口中间：贴着窗口边缘时，往那一边弹出的弹层（侧栏收起后的子菜单）放不下，组件库会把它翻到另一边，各家翻法不一样。

报告最后一行写「几项里几项不一样，一共多少处」。`--mode=native` 只量不比：组件库原生的样子，`report.json` 里每一项的 `values` 就是写适配记录要的「原生实测数字」（这时不一样是正常的）。

## 不量什么（已知的盲区）

- 只查「对齐到控件规格」这一档；原生、只设主题两档不查（它们本来就不一样）。
- 动画过程不查，只查动画结束以后的样子。
- 文字的抗锯齿、字体渲染细节不查（各组件库用的是同一个字体栈）。
- 深色模式、窄屏还没有场景。
- 侧栏收起、展开的过渡动画不查；收起后的子菜单只查鼠标悬停打开，键盘打开（各家做法不一）不查。
- 光标形状（`cursor`）不查。
- 日期面板只查鼠标选日期；面板里用方向键移动（各家做法不一）不查。面板的标题文字（「2026年6月」）、翻月份的箭头不量，只量面板外框和每一天的方块。
- 对话框的遮罩不量（不是部件）；动画、收起的过渡不查。
- 分页只有 5 页，页数多时的省略号不查。

检查说「全部一致」，只代表它量了的那些一致。发现新的盲区，就把它变成一条通用的量法加进来。

## 文件

| 文件              | 是什么                                                     |
| ----------------- | ---------------------------------------------------------- |
| `run.mjs`         | 主程序（Node）：启动检查页、开 Chrome、逐项检查、写报告    |
| `lib/chrome.mjs`  | 最小的 Chrome 遥控器：打开页面、执行代码、真实的鼠标和按键 |
| `lib/compare.mjs` | 对比规则和报告里的中文路径                                 |
| `page/types.ts`   | 检查工具和检查页之间的约定：组件库、目标、检查项、场景     |
| `page/measure.ts` | 在页面里量：按区域、按部件                                 |
| `page/harness.ts` | 检查页这一侧的接口 `window.__audit`                        |
