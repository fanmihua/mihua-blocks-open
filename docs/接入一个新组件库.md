# 接入一个新组件库

> 第二版（2026-10-11）。初稿写完后，让一个没参与过开发的 AI 只照这份说明接入了 TDesign Vue（第五个组件库），卡住和含糊的地方都改进来了。
> 写给 AI 照着执行，设计师也看得懂。每一步都写了：做什么、改哪个文件、怎么算做完。代码细节交给 AI，判断交给人。

比如你要把 Naive UI 接进来。做完以后：同一个登录框（以后还有列表页），换成新组件库渲染，和其他组件库**量出来一样、用起来一样**；自动检查会证明这一点。

**检查工具不认识任何组件库。** 接一个新组件库 = 写一个套件 + 在登记表里加一行，不用为它改检查工具。但组件库多了，检查的量法或环境可能暴露问题（比如页面比检查窗口还宽）——这时可以改检查工具，**只能改成对所有组件库都成立的通用规则**，不能为某个组件库开特例。

---

## 先认识几样东西

| 名字 | 是什么 | 在哪 |
|---|---|---|
| **规范** | 品牌的决定：主色、圆角、控件高度、字号……（Design.md 读进来就是它） | `spec/src/roles.ts`、`spec/src/builtin.ts` |
| **控件规格** | 每种控件统一成什么样，从规范算出来；所有组件库都对齐到它 | `spec/src/controls.ts` |
| **套件接口** | 一个组件库要提供哪些东西：Provider、每种控件、部件地图、组件库档案、适配记录 | `react/src/kit/types.ts`、`vue/src/kit/types.ts` |
| **套件** | 一个组件库一份，把接口翻译成这个组件库的真组件 | `react/src/kits/*`、`vue/src/kits/*` |
| **登记表** | 演示页、检查页、自动检查都按它决定有哪些组件库 | `examples/src/kits.ts`、`examples/src/kits.css` |

参照现成的五个套件：React 看 `react/src/kits/antd`（CSS-in-JS、主题 token）、`arco`（Less 编译、尺寸写死）、`shadcn`（源码在手里、Tailwind 类名）；Vue 看 `vue/src/kits/element`（SCSS、CSS 变量）、`tdesign`（Less、CSS 变量组合在 `:root` 上、无障碍补得最多）。**挑一个和新组件库样式写法最像的照着写。**

## 第 1 步：装上组件库，调研，填组件库档案

先把组件库装上（样式表、源码都在 `node_modules` 里，装上才看得到）：

```bash
npm install <组件库>@<最新稳定版> <它的图标包> -w @mihua/react --save-optional   # Vue 组件库换成 -w @mihua/vue
```

记下装的版本号。然后把这个组件库「是怎么写的」弄清楚，再动手。答案写进套件的 `profile`（类型是 `spec/src/adaptation.ts` 里的 `LibraryProfile`），每一项回答一个问题：

| 项 | 回答什么 |
|---|---|
| `framework` | React 还是 Vue？ |
| `site` | 官网 |
| `tags` | 两三个短标签，一眼看出样式和主题怎么做（比如「Less 样式表」「CSS 变量」） |
| `styling` | 样式是怎么写的？CSS-in-JS、Less / SCSS 编译、还是 Tailwind？类名有没有随机后缀？**样式是你自己引入，还是组件的 JS 自己插进页面？** |
| `theming` | 主题从哪进？运行时能改什么、只能编译时改什么？颜色要不要自己算浅色梯度？**变量在哪一层组合**（见下面）？ |
| `sizing` | 尺寸有几档、各多高？能不能设任意高度？大号除了更高还变了什么（字号、留白）？哪些地方写死了？ |
| `look` | 默认长什么样？主色、圆角、复选框大小、标签栏样式、按钮字重…… |
| `icons` | 图标在哪个包？组件里的图标能不能换、从哪个属性换？有没有全局替换的办法？ |
| `accessibility` | **无障碍**：开关、标签栏、复选框、选择框、菜单有没有角色（role）、能不能用 Tab 和方向键、读屏读不读得到名字、aria 属性落在哪个元素上、聚焦看不看得出来（见下面第 5 条） |
| `setup` | 接进项目要做的事：引入哪个样式表、外面包什么、弹层默认挂在哪 |

**怎么查**：

1. 读官方文档的「主题定制」「全局配置」两章。
2. 打开它的样式表，搜几个关键尺寸（32px、40px）看是写死还是变量。
3. **看变量在哪一层组合**：如果 `:root` 上写着 `--x-primary: var(--x-primary-7)`、`--x-font-body: 14px / 22px 字体` 这种「用变量拼出来的变量」，在外层容器上只改底层（`--x-primary-7`、字体）是不起作用的——CSS 变量在声明它的元素上就算好值了。要改就得直接改组合好的那一层。（TDesign 就是这样；Element 大部分不是，只有导航菜单那一组变量在 `:root` 上拼好了，套件照它的写法在外层再写一遍。）
4. **看样式怎么进页面**：打开组件的 JS 入口（比如 `node_modules/<库>/es/button/index.mjs`），看有没有 `import './style/…'`。有的话，默认入口会自己把样式插进页面，第 3 步「放进单独的层」就做不到；去找它有没有**不带样式的产物**（TDesign 的 `lib/`），组件从那里引入，样式表自己引入。
5. **看无障碍**：读几个控件的渲染代码（或者在演示页里按 Tab、空格、方向键试），开关、标签栏、复选框、选择框是不是用了带 `role` 的元素、能不能用 Tab 聚焦、读屏能不能读到名字。组件不认识的属性（`aria-label`、`inputmode`……）最后落在哪个元素上。TDesign 的开关和标签栏是普通 `div`，整个不能用键盘。

**做完的标志**：十项都填了，每项一两句话，具体到数字。

## 第 2 步：建套件文件，登记依赖和许可

1. 新建套件文件：
   - React 组件库：`react/src/kits/<名字>/index.tsx`，需要样式表再加 `styles.css`；
   - Vue 组件库：`vue/src/kits/<名字>/index.ts`，需要样式表再加 `styles.css`。
2. 在对应包的 `package.json` 里：
   - `exports` 加上这个套件（和它的 `styles.css`）；
   - 第 1 步装的组件库和图标包在 `optionalDependencies` 里（用到哪个组件库才装哪个）。**套件直接 `import` 的包都要写**，哪怕它已经是组件库自己的依赖（比如 TDesign 的图标包）。
3. 把组件库的许可证放进 `licenses/`，在 `THIRD_PARTY_NOTICES.md` 加一行。

## 第 3 步：写 Provider（「只设主题」这一档）

Provider 收到两样东西：`tokens`（规范算好的取值）和 `aligned`（要不要对齐到控件规格）。

1. **`tokens` 为 `null`**：什么都不做，保留组件库原生的样子（演示页的「组件库原生」）。
2. **有 `tokens`**：把规范的取值翻译成这个组件库的主题设置——主色、悬停色、文字色、边框色、圆角、控件高度、字号、字体、动效时长。参照 antd 的 `antdTheme`、Element 的 `elementVariables`、TDesign 的 `tdesignVariables`。
   - 组件库要「浅色梯度」（比如 Element 的 light-3…light-9、Arco 的 1–7 档、TDesign 的 hover / focus / active / disabled / light）而不会自己算的，用 `@mihua/spec` 的 `tint`、`shade` 算好给它。
   - 变量在 `:root` 上组合好的（第 1 步第 3 条），直接写组合好的那一层；字体这类「简写」变量（`字号 / 行高 字体`）要整条重写。
   - 主题设置写在套件的包裹元素上，只影响这个组件，不影响页面上别的地方。
   - 规范里有、组件库没有变量的（比如动效时长写死了），写进档案的 `theming`，不硬改。
3. **弹层挂载点**：下拉、弹窗要挂在组件作用域里（React 用 `usePortal()`，Vue 在 Provider 里放一个 `.mh-portal`），不能挂到 `body`——挂到外面就拿不到规范的 CSS 变量。挂载点要抵消外层的 CSS 缩放（照抄现有套件的 `cancelAncestorZoom`）。组件库有全局配置的（TDesign 的 `ConfigProvider` 的 `globalConfig.attach`），在 Provider 里配一次，不用每个组件单独写。
4. **全局样式放进 cascade layer**：组件库的样式表常带 `html`、`body`、`*` 的全局重置，用 `@import '…' layer(<名字>)` 放进单独的层。
   - 放进层以后还有个好处：套件自己的对齐样式写在层外，天然比组件库的优先，不用比选择器优先级。
   - 例外：带 `!important` 的规则放进层里反而更优先，挡不住。搜一下样式表里的 `!important`，影响页面的记进档案的 `setup`。

**做完的标志**：能渲染出来。演示页切到「只设主题」，颜色、圆角已经跟着规范变了。

---

## 第 4 步：实现每个控件

套件接口里有几个控件就实现几个——**以接口文件为准**（`react/src/kit/types.ts`、`vue/src/kit/types.ts`；写这一版时是 Button、Input、Checkbox、Tabs、Select、Switch，以后会多）。每个控件：

1. 用组件库自己的组件，属性和事件对上接口（`value` + `onChange` / `v-model`、`invalid`、`disabled`、`size`、`loading`……）。
2. **看属性最后落在哪个元素上**：`aria-label`、`aria-describedby`、`inputmode` 这些要落在真正的 `<input>`、`<button>` 上。组件库只把认识的属性交给里面的元素、其余落在外层 `div` 的（TDesign 的输入框），套件渲染完以后转过去。
3. 尺寸两档：接口的 `size: 'default' | 'large'` 对应规范的 `size.control` 和 `size.controlLarge`。组件库的档位和规范对不上时（比如 Arco 只有 28 / 32 / 36），先选最接近的一档，再把高度精确改成规范值。
4. 业务状态（输入的值、勾没勾、当前标签）一律由外面传进来，控件不自己存。

**做完的标志**：`npm run typecheck` 通过（漏了哪个控件它会报）；演示页里每个控件都能用。

---

## 第 5 步：写部件地图

在套件的 `parts` 里写：每个部件（输入框外框、选择框、复选框方块、按钮、标签栏指示条、下拉弹层、下拉选项……）在这个组件库里是哪个元素。部件名和说明在 `spec/src/parts.ts`。

- 找**用户看得见的那个框**（有底色、有边线的那个），不是外面包着的、也不是里面隐藏的 `input`；弹层也一样，找有底色、阴影的那一层，不是只管定位的外壳；
- 一个选择器只能找到一种部件：组件库的选择框里面也套着一个输入框的（TDesign），输入框外框的选择器要把它排除掉；
- 组件库用伪元素画的，写成 `{ selector: '…', pseudo: '::after' }`；
- 只给检查工具用，不影响组件本身。
- **第 8 步改了画法**（比如藏起组件库的指示条、由套件自己画），要回来同步改这里。

**做完的标志**：typecheck 不再报 `parts` 缺项。

## 第 8 步：逐个控件对齐

按控件规格（`spec/src/controls.ts`）一项一项对齐。所有取值都读 `--mh-c-*` 变量或 `resolveControls(tokens)` 的数值，不写死。

**手段从省事的先试**，前一种够不着才用后一种：

| 手段 | 例子 |
|---|---|
| 全局主题变量 | antd 的 `token`、Element 的 `--el-*` 变量、TDesign 的 `--td-*` 变量 |
| 组件主题变量 | antd 的 `components.Button`、组件上自己声明的变量 |
| 组件属性 | Arco 输入框的 `height`、Element 下拉的 `offset`、TDesign 选择框的 `valueDisplay` |
| 全局配置 | TDesign `ConfigProvider` 的 `globalConfig`（弹层挂载点、按名字替换组件内置图标）。适配记录里归到「组件属性」或「补交互」 |
| 换类名 | 源码在自己手里的（shadcn）直接换类名 |
| 样式覆盖 | 组件库没留接口，在套件 `styles.css` 里逐项改，**只在 `--aligned` 下生效**，不用 `!important` |
| 补交互 | 键盘、显隐这类行为不一样，套件补上或改写，**只在对齐时生效**，原生那一档保留组件库自己的做法（但受控状态、弹层挂载点、不真跳转这类接口约定三档都要成立，见「给套件加一个新控件」第 4.3 步） |

**补交互包括无障碍**：开关要有 `role="switch"`、能 Tab 聚焦、空格回车能切；标签栏要有 `tablist` / `tab` / `aria-selected`、只有选中的在 Tab 顺序里、← → 能切；选择框的焦点元素是 `combobox`；复选框的焦点在复选框本身。检查的「Tab 顺序」按角色和名字记，这些不一样它都会报。

**JS 写成行内样式的够不着**：组件库用 JS 算好位置、写成行内样式的（TDesign 标签栏的指示条），CSS 只有 `!important` 压得住。这时接上规范时把它藏起来，由套件自己画（伪元素），再回第 5 步改部件地图。

**判断要不要统一**：问三个问题——这处不同会不会影响**业务状态**？会不会影响**用户看到的结果**？会不会影响**操作结果**？三个都不会，就保留组件库原来的做法。

**图标**：界面上的图标（下拉箭头、密码显隐、对勾、加载）用规范图标集里的（React、Vue 的 `Icon`）。组件库留了图标位（`suffixIcon`、`arrowIcon`、`loading-icon`……）就塞进去；能按名字全局替换图标的（TDesign），用它替换；只能用 CSS 画的（复选框的对勾）用 `--mh-icon-*` 做 CSS 遮罩；连位置都没留的，套件自己画（参照 `PasswordToggle`）。规范写 `icon.set: native` 时保留组件库自带的图标。

**怎么快速迭代**：改样式时只跑控件样张（1 分半），全过了再跑登录框（3 分半），两个都过了最后跑一遍完整的 `npm run check`。报告里的差别眼睛看不出来时（半个像素），先在演示页里量实际样式，确认原因再改；是检查量法的问题，按开头说的改成通用规则。

---


**碰到设计层的分歧**（这个组件库的做法和规格不一样，但它也有道理，比如它有一个别的库没有的能力，或者缺一个别的库都有的能力）：不要自己悄悄定。先看 `docs/取舍记录.md` 里有没有定过；没有就记一条（现象、各库怎么做、选项、推荐，标「待人决定」），先按推荐做、不阻塞，做完时交给人定。判断顺序：用户能不能用（无障碍、键盘）> 设计一致 > 哪个库补起来省事。

## 第 9 步：写适配记录

每处「组件库默认和控件规格不一样」写一条，放进套件的 `adaptations`：

```ts
adapt('tabs', 'size', ['标签高 46px', 'Tabs are 46px'], ['取规格的 40px', '40px from the spec'], 'component-token')
```

五个参数：哪个控件、哪方面、组件库默认怎么样、对齐成什么样、用的什么手段。演示页和文档直接读它，不另写说明。

「哪方面」里**键盘和无障碍分开记**：组件库支持键盘、只是按键做的事或聚焦的样子不一样，记 `keyboard`（antd 标签栏 ← → 只移焦点）；读屏和只用键盘的人用不了或用不好——没有角色、Tab 进不去、读不到名字、aria 落错元素——记 `a11y`（TDesign 的开关是普通 div）。

「组件库默认」写的是**组件库原生的数字**，不是接上规范之后的（比如 TDesign 标签栏一项默认 48px 高，不是接上规范、只设主题以后量到的数）。写完对着第 1 步查到的数字核对一遍。

## 前面五个组件库踩过的坑

- **尺寸写死在编译结果里**（Arco）：只能用组件属性或行内样式改高度，档位要自己选最接近的一档。按钮还要另外管左右留白，不能跟着组件库的档位走。
- **组件在自己身上重新声明变量**（Element）：外层改变量够不着，要写在组件的类名上。默认按钮甚至把高度写死 32px，只有大号、小号读变量。
- **变量在 `:root` 上就组合好了**（TDesign）：外层只改色板、字体这些底层变量不起作用，要改组合好的那一层。
- **组件的 JS 自己把样式插进页面**（TDesign 的默认入口）：样式进不了 cascade layer。改从不带样式的产物（`lib/`）引入组件，样式表自己引入。**组件库引的包也会这样**：TDesign 的图标包默认入口插进一份不在层里的 `.t-icon{width:1em}`，把菜单图标压成 14px，要在构建配置里把它指到不带样式的入口（`examples/vite.config.ts`）。
- **运行时生成的样式选择器优先级**（antd）：套件样式要写两个类名才压得过。
- **需要宿主项目有 Tailwind**（shadcn）：样式表里的 `@theme`、`@source` 要和 `@import 'tailwindcss'` 在同一份入口里处理，所以在 `kits.css` 登记。
- **弹层默认挂在 body**：拿不到规范的 CSS 变量，下拉变回组件库的默认样子。一律挂在作用域内的挂载点。
- **键盘行为不一样**：标签栏的方向键（antd 只移焦点、Arco 不支持）要套件补齐。自动检查会按 Tab、按方向键、按回车来核对。
- **整块的无障碍缺口**（TDesign）：开关、标签栏是没有 `role` 的 `div`，不能用键盘；复选框的焦点落在 `<label>` 上；输入框的 `aria-*` 落在外层 `div` 上；选择框不是 `combobox`。都在套件里补。
- **JS 算好写成行内样式**（TDesign 标签栏指示条）：CSS 改不动位置，藏起来由套件画。
- **奇数字号差半个像素**（TDesign 按钮）：文字框是一整行高还是一个字高，在 15px 这种字号下取整方向不同。按钮文字统一成一个字高、由按钮居中。
- **页面比检查窗口宽**（第五个库进来时）：双栏登录五格排开 4088px，超过检查窗口的 3400px，最左边的格子点不到。检查工具改成「鼠标操作前先把目标滚进窗口」；后台页面框架五格要 6000 多 px，贴边的目标再改成滚到窗口中间。
- **组件库自己发事件、自己存状态**（后台页面框架的菜单）：Element 挂载时自己发「展开」，antd 叶子回车记成「展开」，TDesign 悬停报「展开」。套件只转告用户的意图，见「给套件加一个新控件」第 4.3 步。
