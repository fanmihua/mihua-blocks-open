# 只借方法：已有项目不换结构，也能和设计稿对上

> 写给 AI 照着执行，设计师也看得懂。

这个仓库的完整用法是「页面用我们的视图和控制器、组件库换成套件」。但你可能已经有一个用 Ant Design（或别的组件库）写好的后台，不想动结构，只想让它**和设计稿（Design.md）对上**，并且**有办法证明对上了**。这时只借三样东西：

| 借什么 | 在这个仓库里是 | 你的项目里变成 |
|---|---|---|
| 控件规格 | `spec/`：规范 → 语义角色 → 控件规格 → CSS 变量 | 页面根上的一组 `--mh-*`、`--mh-c-*` 变量 |
| 样式覆盖 | 每个套件的 `styles.css`（只写组件库主题改不到的部分） | 你项目里一个样式文件 |
| 检查 | `audit/`：量看得见的部件，逐项对比 | 一段对照「规格数」的检查（或者借这里的检查页） |

不借的：视图（`react/src/blocks`、`vue/src/blocks`）、控制器（`core/`）、套件接口。你的页面结构、状态管理、路由一行不改。

---

## 第 1 步：把设计稿变成 CSS 变量

设计稿是一份 `Design.md`（照着 `designs/mono/Design.md` 写：开头一段元信息，正文里一个 `mihua-tokens` 代码块；格式的读写在 `spec/src/markdown.ts`）。用规范层把它算成两组变量：语义角色（主色、正文色、控件高度……）和控件规格（表格行高、对话框留白……）。

```ts
import {
  controlCssVariables,
  parseDesignMarkdown,
  resolveControls,
  resolveSpec,
  toCssVariables,
} from '@mihua/spec';

const { spec } = parseDesignMarkdown(designMarkdownText);
const tokens = resolveSpec(spec);
const variables = { ...toCssVariables(tokens), ...controlCssVariables(resolveControls(tokens)) };

// 写到你页面的根上（或者生成一个 :root { … } 的样式文件）
for (const [name, value] of Object.entries(variables))
  document.documentElement.style.setProperty(name, value);
```

`@mihua/spec` 没有发到 npm：把 `spec/` 整个目录拷进你的项目（它只依赖 zod），或者用上面的代码生成一份静态的 CSS 文件放进去。

**怎么算做完**：浏览器开发者工具里，页面根上能看到 `--mh-action-primary`、`--mh-c-table-row-height` 这类变量。

## 第 2 步：先把取值交给组件库的主题

组件库自己的主题接口能管到的，交给主题接口（最省事、最不容易坏）。照这个仓库对应套件的写法抄一份：

- antd：`react/src/kits/antd/index.tsx` 里的 `antdTheme(tokens)`，交给 `ConfigProvider theme`；
- Arco：`react/src/kits/arco/index.tsx` 的 Provider 部分（CSS 变量 + `ConfigProvider`）；
- Element Plus、TDesign：`vue/src/kits/element/index.ts`、`vue/src/kits/tdesign/index.ts` 的 Provider 部分（`--el-*`、`--td-*` 变量）；
- shadcn：`react/src/kits/shadcn/index.tsx` 的 `shadcnVariables`。

只抄你页面用到的控件。

## 第 3 步：写一个样式覆盖文件

主题接口改不到的（表格的行高、排序按钮、日期面板的格子、对话框的关闭按钮……），在一个样式文件里逐项改。照对应套件的 `styles.css` 抄你用到的那几节，把作用域类换成你项目的根类：

```css
/* 原来（套件里）：只在「对齐」那一档生效 */
.mh-kit-antd.mh-kit-antd--aligned .ant-table-tbody > tr > td { height: var(--mh-c-table-row-height); padding-block: 0; }
/* 你的项目里 */
.your-app .ant-table-tbody > tr > td { height: var(--mh-c-table-row-height); padding-block: 0; }
```

规则和套件一样：

- **取值一律读变量**（`--mh-c-*`），不写死颜色和尺寸；
- 选择器比组件库生成的多一个类就够，**不用 `!important`**；
- 键盘、读屏缺的（排序按钮、分页的角色、对话框的焦点）也照套件补：有的写在套件的组件里（`index.tsx` / `index.ts` 里的 `useLayoutEffect`、`patchAfterRender`），搬到你包组件库的那一层。每一处为什么补，看套件的 `adaptations`（适配记录）。

## 第 4 步：检查

### 轻量：对照规格里的数

在你的页面上（开发者工具的控制台里）跑一段对照：每一行写「哪个元素、哪个属性、应该等于哪个规格变量」。

```js
const rows = [
  ['.ant-btn', 'height', '--mh-size-control'],
  ['.ant-table-thead > tr > th', 'height', '--mh-c-table-head-height'],
  ['.ant-table-tbody > tr > td', 'height', '--mh-c-table-row-height'],
  ['.ant-tag', 'height', '--mh-c-tag-height'],
  ['.ant-pagination-item', 'height', '--mh-c-pagination-item-size'],
];
const root = getComputedStyle(document.documentElement);
for (const [selector, property, variable] of rows) {
  const el = document.querySelector(selector);
  const want = root.getPropertyValue(variable).trim();
  const got = el ? getComputedStyle(el).getPropertyValue(property) : '找不到元素';
  console.log(got === want ? '✓' : '✗', selector, property, got, '应该是', want);
}
```

颜色也一样（`background-color` 对 `--mh-c-table-head-background`……；注意变量写的是十六进制，计算出来的是 `rgb(…)`，比之前先换算一下）。这一段可以放进你的端到端测试（Playwright 的 `page.evaluate`）。

它只能证明「量到的数等于规格」，量不到交互（悬停、键盘、弹层）。

### 完整：借这里的检查页

想要和这个仓库一样的检查（按区域、按部件量位置、颜色、边线，再用真实的鼠标键盘核对交互），把你最在意的一块（比如表格）搬进这里的检查页，和 shadcn 参照实现并排比：

1. 照 `docs/接入一个新组件库.md` 给你的组件库建一个最小套件：只实现这一块用到的控件，Provider 用第 2 步的主题，样式用第 3 步的覆盖文件，部件地图写你项目里的类名。
2. 在 `examples/src/scenes/` 写一个场景，渲染这一块（可以直接用这里的视图，比如 `CustomerList`；也可以把你的组件搬进来）。
3. `npm run audit:kits -- --scene=<你的场景> --kits=shadcn,<你的套件>`。

---

## 和完整用法比，少了什么

- 换组件库不再是「换一个套件」：你的页面直接用组件库的组件，换库还是要改页面。
- 业务状态（筛选、勾选、对话框里的表单）在你自己的代码里，换框架不能共用。
- 检查只能证明你量了的那些对上了（轻量检查尤其如此）。

但「设计稿怎么变成取值」「组件库改不到的地方怎么改、改在哪」「怎么证明改对了」这三件事，和完整用法一模一样。
