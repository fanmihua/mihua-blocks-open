# 记一条取舍

AI 不能自己悄悄定设计层的分歧。打开 `docs/取舍记录.md`，先看有没有定过；没有就照它开头的格式记一条：

- **现象**：用户在哪儿会碰到。
- **各库**：五个组件库各怎么做（实测，不猜）。
- **选项**：A / B / C。
- **推荐**和理由。判断顺序：用户能不能用（无障碍、键盘）> 设计一致 > 哪个库补起来省事。四种情况：某个库做法更好 → 吸收进设计；某个库缺能力 → 套件补；差异不影响结果（业务状态、用户看到的结果、操作结果都不受影响）→ 保留原生；都不是我们要的 → 按自己的设计。
- 标 **「待人决定」**。

可以先按推荐做、不阻塞；做完时把所有「待人决定」一起列给人。人定了以后改成「已定」，写上谁定的、哪天；改了主意要写为什么。
